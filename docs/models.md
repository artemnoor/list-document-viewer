# Модели и размещение

## Демонстрационный контур

Для воспроизведения модельных этапов задайте **свой `POLZA_API_KEY`** в `phystech-trace/.env`. Ключ используется сервером. Демонстрационный провайдер — Polza AI, OpenAI-compatible endpoint `https://polza.ai/api/v1`.

| Компонент / роль | Использование |
|---|---|
| OCR и структура | Docling, нативные адаптеры PDF/Office, Cyrillic PP-OCRv5 ONNX; локальное CPU-исполнение Parser |
| `google/gemma-4-26b-a4b-it` | Выбранный модельный маршрут Gemma: интерпретация/связывание и модельные этапы согласно настройкам проекта |
| `deepseek/deepseek-v4.1-flash` | Модельный маршрут для открытых документов; извлечение, связывание и планирование согласно настройкам |
| `local-cost-audit/1.1` | Сопоставление явных статей, Decimal-агрегирование и проверка без модельных вызовов |

Использование Polza AI в демостенде — способ воспроизвести выбранные модели по пользовательскому ключу. Для внешнего API используются только открытые, синтетические или обезличенные документы. Название Gemma в интерфейсе не является доказательством локального размещения: в данной Compose-конфигурации её модельные запросы направляются провайдеру.

## Почему выбор проверяется экспериментом

Финансовый расчёт требует разных свойств: понимания русскоязычного документа, точного копирования ID, соблюдения JSON-контракта, устойчивости к дублям/периодам и приемлемого времени ответа. Оценивать эти свойства одним названием модели нельзя.

14 ноября 2026 выполнен одинаковый эксперимент для Gemma 4 26B A4B и Qwen3.8 27B. ID обеих моделей проверены в каталоге Polza. Шесть публичных синтетических текстовых задач, два повтора, `temperature=0`, `max_tokens=2048`; совпадение всех трёх полей проверяется строго.

| Метрика | Gemma 4 26B A4B | Qwen3.8 27B |
|---|---:|---:|
| Выполнено вызовов | 12 | 12 |
| Полностью верные ответы | 8/12 | 12/12 |
| Верная ожидаемая сумма | 9/12 | 12/12 |
| Верный статус | 11/12 | 12/12 |
| Точные ID источников | 9/12 | 12/12 |
| Среднее время запроса | 1,68 с | 5,36 с |
| Ошибки HTTP/JSON | 0 | 0 |

На этом наборе Gemma отвечала примерно в 3,2 раза быстрее, Qwen точнее выполнила строгий контракт. Это наблюдение по конкретным шести текстовым задачам, а не универсальное ранжирование моделей на документах или OCR. Числа 26B A4B и 27B в названиях не означают равенства архитектур или вычислительной стоимости.

[Все входы, gold, ответы, prompt SHA256, usage и времена](../benchmarks/results/model-comparison.json) · [проверяющий скрипт](../benchmarks/models/compare.mjs). Сохраняется и [первый прогон](../benchmarks/results/model-comparison.initial.json) с бюджетом 512 токенов. Бюджет и инструкция по ID затем одинаково уточнены для обеих моделей; исходные результаты не удалены.

## Локальный контур

Для локального размещения модельного этапа нужен отдельный inference-сервер с подходящими весами, ресурсами и совместимым API. После настройки серверного маршрута необходимо повторить тот же корпус и проверить, что документы не уходят к внешнему провайдеру. Локальный Parser и детерминированный расчёт уже выделены в самостоятельные компоненты; модельные роли изолированы от Decimal-арифметики и источников.

Официальные источники весов и инструкций: [Google Gemma](https://ai.google.dev/gemma/docs/core), [Gemma 4 26B A4B](https://huggingface.co/google/gemma-4-26B-A4B), [Qwen3.8 27B](https://huggingface.co/Qwen/Qwen3.8-27B). Эти страницы подтверждают доступность моделей для самостоятельного размещения; качество нашего приложения проверяется собственным корпусом, а не переносится из модельной карточки.

Практический путь внедрения: зафиксировать модель/квантизацию и оборудование → настроить endpoint → проверить поток данных → выполнить одинаковые повторы на размеченном корпусе → сравнить точность, JSON-контракт, задержку и стоимость. Само наличие open-weight модели не означает, что текущий демостенд уже исполняет её локально.
