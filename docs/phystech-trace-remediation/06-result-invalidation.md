## Объём следующего стабильного MVP

**Вердикт пользователя: Сейчас.**

Снимать актуальность зависимых результатов при изменении входов, сохранять историю и проверять manifest при публикации.

Объём ниже уточнён по пользовательской оценке всех 35 планов. Расширенные решения не являются обязательствами MVP; отложенное замечание не считается устранённым. Исследование остаётся без реализации.

## Что подтверждено

Статически подтверждён риск сохранения старого результата; параллельный сценарий здесь не воспроизводился.

- [phystech-trace/gateway/main.py](../../phystech-trace/gateway/main.py) — set_project_status использует COALESCE для linking_result и linking_job_id; upload_documents не снимает current result; retry может использовать existing_job.

## Причина и границы вывода

None означает одновременно «не менять» и «очистить». Результат и job ID не привязаны к неизменяемой ревизии входа.

## Рекомендуемое решение

Разделить отсутствие patch-поля и явный NULL. Хранить immutable linking_runs, а в проекте — current_run_id, input_revision и stale reason. Удалять текущую ссылку при изменении зависимостей; история остаётся доступна с её точным manifest.

## Последовательность будущего изменения

1. Единая операция мутации входов в транзакции повышает revision, инвалидирует extraction/linking по DAG зависимостей и current pointer.
2. Retry/resume допустим только при полном совпадении manifest, конфигурации и политики; иначе создать новый run и ключ идемпотентности.
3. Для single-process MVP публикация результата использует compare-and-set по input_revision и active_run_id. Исторический результат не становится current другой revision. Полноценный fencing token добавить при переходе к распределённому исполнению по №13; run_id не считать его заменой для нескольких replicas.
4. UI очищает выбранное evidence при смене ревизии; старый граф показывается только в явно обозначенной истории.

## Проверка исправления

- После completed добавить новый документ, повторить Extraction, поменять роль КФЗ или настройки обработки — прежний граф не current.
- Старый run завершается после новой загрузки: его результат не перезаписывает current revision; retry не возобновляет старый job.

## Критерий закрытия

API различает historical/current/stale; ни один граф не выдаётся актуальным при несовпадении его входов с текущим комплектом.
