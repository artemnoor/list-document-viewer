## Объём следующего стабильного MVP

**Вердикт пользователя: Сейчас.**

LLM определяет смысл, точные значения и provenance берутся из Parser; строгий grounding сохраняется.

Объём ниже уточнён по пользовательской оценке всех 35 планов. Расширенные решения не являются обязательствами MVP; отложенное замечание не считается устранённым. Исследование остаётся без реализации.

## Что подтверждено

Отклонение POLZA_UNGROUNDED_OUTPUT и rules_only в E2E подтверждены отчётом; точная первопричина конкретного ответа ещё не установлена.

- [phystech-trace/docs/integration-report.md](../../phystech-trace/docs/integration-report.md) — LLM-assisted отказал; успешные Extraction/E2E относятся к rules_only.
- [phystech-trace/services/structured-extraction/lib/extraction/polza-ai.mjs](../../phystech-trace/services/structured-extraction/lib/extraction/polza-ai.mjs) — buildGroundedContext: бюджет 34000 символов, выбор первых восьми/последней строки; validateGrounding и callPolzaForExtraction проверяют ID и заголовки.

## Причина и границы вывода

Возможные причины: модель меняет ID, цитирует строку вместо заголовка либо ссылается на элемент, не попавший в ограниченный контекст. Проверка кода выявляет эти гипотезы, но не выбирает одну без безопасно сохранённого ответа и контекста неуспешного запроса.

## Рекомендуемое решение

Оставить строгий grounding. Модель предлагает смысл полей и колонок через допустимые source_element_id и точные цитаты; сервер извлекает типизированные значения из авторитетного Parser JSON. Извлечение выполняется над Parser-структурами, а не отправкой исходных Office-файлов напрямую в LLM.

## Последовательность будущего изменения

1. Сохранить на синтетическом корпусе request/context hash, ответ и diagnostics по каждой неподтверждённой ссылке. Отделить invalid JSON, schema mismatch, неверный ID и отсутствие цитаты.
2. Разделить классификацию, mapping заголовков и extraction полей; повторять только дефектную часть. Для больших таблиц обеспечить покрытие всех строк либо явно зафиксировать, что LLM анализирует схему, а строки обрабатываются детерминированно.
3. Добавить строгий режим llm_assisted_required: fallback виден и не засчитывается как прохождение LLM. Не ослаблять требования к source_value и provenance.

## Проверка исправления

- Live PDF, DOCX, XLSX, смешанный PDF/OCR, многостраничная таблица, повторные заголовки, merged cells, формулы и пустые ячейки.
- Неверные ID/цитаты, изменённые суммы и выдуманные координаты отклоняются; неизвестные значения остаются неизвестными.

## Критерий закрытия

Есть успешный live LLM-путь для каждого заявленного формата и сложных таблиц, с отчётом точности/покрытия и разрешением evidence. Ни один обязательный тест не проходит за счёт rules_only.
