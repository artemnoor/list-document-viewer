## Причина и границы вывода

Текущее разбиение переносит узкое место в финальное объединение сводок и evidence registry. Увеличение лимита не обеспечивает масштабируемость; один огромный элемент также может превысить бюджет фрагмента.

## Рекомендуемое решение

Сохранить сервис и контракты, заменить глобальный LLM reduce ограниченными заданиями: обзор каждого документа, извлечение кандидатов между документами, проверка ограниченных групп строк, детерминированное объединение проверенных утверждений. Каждый вызов получает точные reference_id, а исходные значения разрешаются сервером.

## Последовательность будущего изменения

1. Задать лимиты комплекта: файлы, страницы, строки, байты JSON, максимальный отдельный элемент, токены, время и стоимость. Preflight выдаёт прогноз и явный отказ сверх лимита.
2. Построить устойчивый план чанков с hash и checkpoint. Разбивать крупные таблицы по строкам с повтором заголовков, сохраняя исходные пути.
3. Не отсекать кандидатные пары только по равным суммам/номерам. Использовать несколько способов поиска и отдельный проход по пропускам/неоднозначности; измерять recall отбора.
4. Объединять по идентичности концов, направлению и смыслу связи; не вводить закрытый словарь типов отношений. Противоречия сохранять для review.

## Проверка исправления

- Повторить исходный комплект из пяти документов и расширенные наборы в пределах лимитов; проверить межчанковые связи и oversized row.
- Переставить документы и строки; прервать последний чанк; возобновить и сверить coverage и неизменность evidence.

## Критерий закрытия

Нет финального запроса, размер которого растёт до полного содержимого комплекта. Все элементы учтены, неуспехи явно перечислены, полный прогон проходит; качество подтверждено отдельно по №33.
