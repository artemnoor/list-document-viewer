## Объём следующего стабильного MVP

**Вердикт пользователя: Сейчас.**

Получать фактические статусы через Gateway, различать unavailable/unknown/blocked.

Объём ниже уточнён по пользовательской оценке всех 35 планов. Расширенные решения не являются обязательствами MVP; отложенное замечание не считается устранённым. Исследование остаётся без реализации.

## Что подтверждено

Gateway уже выполняет health checks, но UI заявляет готовность без привязки к актуальному результату.

- [phystech-trace/frontend/src/App.vue](../../phystech-trace/frontend/src/App.vue) — Статический текст о готовности сервисов.
- [phystech-trace/gateway/main.py](../../phystech-trace/gateway/main.py) — health проверяет upstream; service_links отдаёт адреса документации, а не полноценную модель свежести.

## Причина и границы вывода

Каталог сервисов смешан с доступностью. Старая успешная проверка или HTTP 200 degraded могут выглядеть как текущее ready.

## Рекомендуемое решение

UI получает агрегированный readiness/capabilities snapshot от Gateway: checked_at, статус каждого сервиса, latency и безопасный reason code. Браузер не обращается напрямую к внутренним адресам и не получает service token.

## Последовательность будущего изменения

1. Переиспользовать улучшенную probe №17. Отделить catalog/docs links от actual health; простой queue status №18 описывать как доступность очереди. Расширенный worker status добавить позже, не делать его prerequisite текущего UI.
2. Обновлять при открытии, видимости вкладки и разумным интервалом с backoff; отображать stale/unknown после срока годности, а не вечный зелёный.
3. Показывать доступность функций: Parser доступен, Linking заблокирован политикой, provider не настроен, сервис недоступен — разные причины.
4. Кнопки объясняют временную недоступность, сервер всё равно проверяет готовность/политику при действии. Добавить ручное обновление.

## Проверка исправления

- Отключить один сервис, оставить Gateway доступным; UI отражает конкретный сбой и восстановление.
- Gateway unreachable, out-of-order responses, background tab, timeout и blocked confidential: статусы не подменяются готовностью.

## Критерий закрытия

Надпись о готовности основана на свежем snapshot, видны время проверки и причины ограничений. Сетевые credentials не попадают в Vue.
