## Объём следующего стабильного MVP

**Вердикт пользователя: Позже.**

Сохранить sheet/cell/value/provenance и открытие оригинала; полноценная подсветка Excel-сетки не блокирует backend MVP.

Объём ниже уточнён по пользовательской оценке всех 35 планов. Расширенные решения не являются обязательствами MVP; отложенное замечание не считается устранённым. Исследование остаётся без реализации.

## Причина и границы вывода

Один адрес не показывает заголовки, единицу измерения и связь строки с другими значениями. Повторный разбор XLSX в браузере может расходиться с Parser snapshot.

## Рекомендуемое решение

На следующем MVP сохранить имеющийся XLSX locator: версия источника, имя листа, адрес, raw/normalized value и ссылка на оригинал. Обязательны точность evidence по №28 и защита source endpoint; сетка с подсветкой отложена.

## Последовательность будущего изменения

1. Не терять существующие sheet/cell/provenance при изменении контрактов и хранения.
2. Проверить правильность исходного файла и версии, различать missing cell/неизвестное значение.
3. Не вводить новый worksheet API, formula engine или браузерный XLSX parser в текущем backend этапе.

## Проверка исправления

- Клик evidence показывает правильные sheet/address/value и открывает верный исходный файл.
- Чужой проект не получает источник; новая версия не подменяет historical evidence.

## Критерий приёмки MVP

Текущий locator остаётся точным и пригодным для ручной проверки через оригинал. Полноценный XLSX viewer пока не реализуется и исходное улучшение остаётся открытым.

## Что отложено

Worksheet slice API, сетка окружения, merged/hidden/sparse/formula отображение, клавиатурная навигация и подсветка — отдельная UI-задача.

Исходная расширенная проработка ниже сохранена как справочный вариант; она не расширяет текущий scope. При расхождении объёма приоритет имеют разделы MVP выше.

## Расширенный вариант для следующих этапов

Фрагмент листа строить из авторитетной native XLSX-структуры соответствующего parser_artifact. Запрос scoped по проекту, artifact, sheet и ограниченному cell range. Выбранная ячейка и merged anchor выделяются, заголовки строк/колонок видны.

## Расширенный вариант: возможные шаги

1. Проверить, какие surrounding cells уже есть в Parser JSON; если их недостаточно, расширить Parser read-only slice API в будущем, не восстанавливать недостающие значения моделью.
2. Учитывать merged ranges, sparse sheets, hidden rows/columns, даты/числовые formats, формулу и сохранённое вычисленное значение раздельно.
3. Не выполнять VBA/формулы и не обновлять external links; значение из snapshot не выдавать за пересчитанное. Ограничить диапазон и размеры ответа.
4. Обеспечить клавиатурную навигацию, текстовый locator и открытие оригинала; отсутствие ячейки/контекста показывать явно.

## Расширенный вариант: будущие проверки

- Листы с кириллицей/апострофом, merged E2:F2, формула без cached value, hidden row и ячейка далеко в sparse диапазоне.
- Чужой project/artifact отклоняется; выбор разных источников не показывает устаревший range из позднего ответа.

## Критерий полного закрытия исходного замечания

Пользователь видит точную source cell с окружением и версией, а raw/normalized/formula различаются. Нет выполнения активного содержимого файла.
