## Объём следующего стабильного MVP

**Вердикт пользователя: Сейчас.**

Запрещать изменение активного комплекта; snapshot остаётся неизменным. Загрузка в будущую revision отложена.

Объём ниже уточнён по пользовательской оценке всех 35 планов. Расширенные решения не являются обязательствами MVP; отложенное замечание не считается устранённым. Исследование остаётся без реализации.

## Что подтверждено

Отсутствие блокировки подтверждено; точная последовательность из претензии требует уточнения.

- [phystech-trace/gateway/main.py](../../phystech-trace/gateway/main.py) — upload_documents не блокирует running; process_project читает document_rows в начале и повторно после Extraction.

## Причина и границы вывода

Повторное чтение изменяемого списка способно включить новый документ без extraction_result, изменить счётчики или привести к ошибке. Поэтому конкретный итог completed не доказан, но несогласованный snapshot — реальный риск.

## Рекомендуемое решение

Для первой безопасной реализации запрещать мутацию комплекта, пока существует активный run, и одновременно сохранять immutable run_documents. Позже можно разрешить загрузку как отдельную будущую ревизию, не меняющую активный run.

## Последовательность будущего изменения

1. Атомарно проверять active run и фиксировать manifest под блокировкой строки проекта; upload и start используют ту же блокировку.
2. Не держать транзакцию во время загрузки в Parser: сначала подготовить артефакт, затем проверить revision и зарегистрировать membership; при конфликте вернуть 409 и поставить непривязанный blob на безопасную очистку.
3. Worker на каждом этапе читает run_documents, а не живой document_rows(project_id). Завершение относится к обработанной revision.
4. В single-process MVP проверить отмену и startup recovery сохранённого active run, чтобы падение не оставляло вечную блокировку изменений. Срок lease проектировать при переходе к распределённому исполнению, а не вводить как обязательную подсистему сейчас.

## Проверка исправления

- Одновременные upload/start из разных процессов и два upload; барьеры до и после записи manifest.
- Загрузка во время Parser, Extraction и Linking; kill владельца run и восстановление права изменения без публикации старого результата.

## Критерий закрытия

Состав run неизменен, операции start/upload сериализованы, интерфейс показывает обрабатываемую ревизию. Недопустимый запрос имеет понятный 409.
