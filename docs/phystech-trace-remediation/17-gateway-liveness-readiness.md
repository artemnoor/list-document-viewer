## Объём следующего стабильного MVP

**Вердикт пользователя: Сейчас.**

Раздельные live/ready, HTTP 503 для неготовности обязательных зависимостей и согласованные container probes.

Объём ниже уточнён по пользовательской оценке всех 35 планов. Расширенные решения не являются обязательствами MVP; отложенное замечание не считается устранённым. Исследование остаётся без реализации.

## Что подтверждено

Возврат dict из health сохраняет HTTP 200 даже для unavailable/degraded.

- [phystech-trace/gateway/main.py](../../phystech-trace/gateway/main.py) — health проверяет SELECT 1 и сервисные /health, возвращая dict без ошибочного status code.
- [phystech-trace/gateway/Dockerfile](../../phystech-trace/gateway/Dockerfile) — Проверить согласование существующей container probe с новыми endpoints.
- [phystech-trace/docker-compose.yml](../../phystech-trace/docker-compose.yml) — depends_on использует service_healthy.

## Причина и границы вывода

HTTP-успех проверяется отдельно от содержания JSON; все зависимости сведены к одному виду готовности. Недоступность внешней модели может блокировать лишь отдельную capability.

## Рекомендуемое решение

/live сообщает, что процесс обслуживает event loop; /ready проверяет БД, схему и обязательные внутренние зависимости в рамках ограниченного времени. При неготовности обязательного компонента — 503, с структурированным списком причин. Для MVP не требуется отдельный dispatcher или расширенная telemetry worker: базовый queue probe №18 имеет явно ограниченный смысл.

## Последовательность будущего изменения

1. Утвердить матрицу обязательных зависимостей для загрузки, rules extraction и linking. Внешний provider outage не должен безусловно скрывать уже сохранённые результаты.
2. Проверять статус JSON зависимости, а не только r.status_code. Добавить unknown при непроведённой probe, deadlines и короткий cache против лавины health requests.
3. Согласовать Dockerfile HEALTHCHECK, Compose overrides и последующий production orchestrator. Live failure и ready failure имеют разные реакции.
4. Не возвращать исключения с credentials; наружу только безопасные коды причин, детали — защищённая диагностика.

## Проверка исправления

- БД недоступна → ready 503, live 200; восстановление возвращает ready 200.
- Upstream /health возвращает 200 + degraded; ready учитывает смысл. Проверить hung dependency и ограниченное общее время ответа.

## Критерий закрытия

Проверка контейнера обнаруживает потерю обязательной зависимости, а живой процесс не перезапускается бесконечно из-за чужого outage.
