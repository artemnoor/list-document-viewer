## Объём следующего стабильного MVP

**Вердикт пользователя: Сейчас.**

Атомарно выделять version и сохранять результат в project scope, используя существующий UNIQUE как дополнительную защиту.

Объём ниже уточнён по пользовательской оценке всех 35 планов. Расширенные решения не являются обязательствами MVP; отложенное замечание не считается устранённым. Исследование остаётся без реализации.

## Что подтверждено

Потенциальная гонка подтверждена структурой storeExtraction; нагрузочно не воспроизводилась.

- [phystech-trace/services/structured-extraction/runtime/server.mjs](../../phystech-trace/services/structured-extraction/runtime/server.mjs) — SELECT MAX(version) → version + 1 → INSERT; UNIQUE(document_id, version) уже существует.

## Причина и границы вывода

Два запроса видят один MAX. Имеющийся UNIQUE защищает от одинаковых сохранённых номеров, но один запрос завершится конфликтом; повторная проверка cache сама по себе не атомарна.

## Рекомендуемое решение

В транзакции блокировать счётчик версии проектного экземпляра. Использовать counter row с INSERT ... ON CONFLICT ... DO UPDATE ... RETURNING либо UPDATE ... RETURNING под row lock. Последовательность глобального sequence проще, но не заменяет ожидаемую отдельную нумерацию документа.

## Последовательность будущего изменения

1. Определить scope версии после №8. Сначала получить атомарное право на idempotency/input fingerprint, затем выделить version и вставить payload в той же транзакции.
2. Оставить UNIQUE(instance_id, version) и UNIQUE(scope, computation_fingerprint). Идентичный конкурентный запрос возвращает тот же artifact, а не создаёт вторую версию.
3. При serialization/deadlock ошибке повторять ограниченно с backoff. Внешний LLM не вызывать внутри длительной транзакции.

## Проверка исправления

- Два процесса синхронно сохраняют разные результаты одного instance: оба успешны, версии уникальны.
- 20 одинаковых idempotent запросов дают один artifact; rollback после выделения counter не оставляет полусохранённый payload.

## Критерий закрытия

Нет необработанных UniqueViolation при штатной конкуренции, нумерация определена контрактом и идемпотентные повторы не размножают версии.
