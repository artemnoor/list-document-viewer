## Причина и границы вывода

Загрузочное runtime-хранилище попало в репозиторий. Производный JSON и метаданные могут раскрывать те же сведения, что оригиналы.

## Рекомендуемое решение

Подготовить отдельный закрытый реестр: git path/blob hash, тип, происхождение, разрешение, владелец проверки, решение. Классы: разрешённый публичный fixture, синтетический, неизвестный, непредназначенный для публикации. Не публиковать извлечённые имена/суммы в общем реестре.

## Последовательность будущего изменения

1. Проверить текущие tracked files и доступную историю, включая переименования, архивы, JSON и отчёты; актуальный count относится только к backend/uploads в HEAD.
2. Разрешённые fixtures перенести в явную tests/fixtures с provenance/лицензией; неизвестные — в закрытый карантин. Runtime uploads удалить из индекса только на будущей стадии исправления.
3. При подтверждённой нежелательной публикации согласовать очистку истории, форков, release artifacts и caches с владельцем репозитория; сначала сделать защищённую резервную копию.
4. После очистки внедрить CI denylist runtime paths, allowlist fixtures и контроль новых binary artifacts. Если найдены credentials — отдельно отозвать их.

## Проверка исправления

- До/после: git ls-files и проверка достижимых объектов/refs по реестру hashes; прежний clone не считается автоматически очищенным.
- Синтетические тесты работают без реальных uploads; попытка добавить runtime artifact блокируется CI.

## Критерий закрытия

Каждый файл классифицирован владельцем; непредназначенные материалы устранены из согласованного охвата. Удаление текущего файла отдельно от очистки истории отражено в отчёте.
