# Исходный baseline до hardening

## Проверка исправлений (14 ноября 2026)

- Сценарий 320 кандидатов ставит единственный ожидаемый источник в строку 308, за пределы стандартного первого пакета из 300.
- Synthetic Linking fixtures подтверждают только ожидаемые факты; прочие автоматически предложенные связи имеют статус review и не выдаются за ручную проверку.
- `_formula_matches()` проверяет структуру дерева и поля исходных шагов перед сравнением формулы; регрессионный тест исключает лишние поля в шаге.
- `_merge_chunk_plans()` прекращает объединение при различиях валюты, единиц или базы расчёта; параметризованные регрессионные тесты проверяют каждое поле отдельно.
- Тест сценария 320 кандидатов проверяет индекс целевого факта за границей первого пакета и наличие как подтверждённых, так и ожидающих проверки Linking-связей.
- Платные LLM-вызовы в тестах не используются.

Проверки 14 ноября 2026 года: `pytest -q` — **успешно, все собранные тесты пройдены** (повторный полный прогон после регрессионных тестов также успешен); `python examples/build_synthetic_acceptance.py` — **успешно**, результат `calculated`, `550.00 RUB`; `docker build --tag reconciliation-engine:ci .` — **успешно**; запущенный контейнер вернул HTTP 200 для `/health`, `/docs` и `/openapi.json`. Реальные платные LLM-вызовы не выполнялись.

## Проверка реального upstream-примера

- `examples/build_upstream_example.py` теперь копирует `input_hash` из каждой Extraction в Linking snapshot и связывает prior decision с точным snapshot через штатный `bind_decision_to_request`.
- Регрессионная проверка подтверждает upstream contracts и отсутствие `stale_human_decision`; `target_period_mismatch` всё ещё блокирует публикацию.
- Gemma 4 26B A4B четыре раза дала план на акте и КФЗ: по пять источников, локальное выполнение плана — `1180300.00`. API-ответ остаётся `manual_review`, `expected_value=null`, поскольку период апреля не соответствует Q1, а путь Linking не подтверждён.
- Полные фактические суммы и ответы модели не сохранялись в репозитории; только безопасная сводка в локальном `data/`.
- После dimension filtering повтор на реальном акте выбрал ровно пять фактов `amount`, не выбрал quantity/unit price и снова локально посчитал `1180300.00`; публикация осталась заблокирована несовпадающим периодом и неподтверждённым Linking.
- Проверка всех шести real Extraction fixtures (113 кандидатов) выявила, что LLM может выбрать денежные суммы и количества в разных единицах. Prompt `calculation-plan.v1.0.2` требует совместимые размерности и полное покрытие кандидатов; кандидаты с явно несовместимой валютой/единицей автоматически исключаются до отправки, а merge повторно проверяет dimensions выбранных Extraction facts. На повторе модель получила 91 совместимого кандидата, дала три ответа с одинаковыми размерами `RUB`/без единицы; диагностики `mixed_units` и `currency_missing` пропали. Ожидаемое значение не опубликовано из-за неразрешённых кандидатов, несовпадения периода и отсутствия подтверждённого Linking.

Проверено 13 ноября 2026 года.

- `pytest`: **46 passed** в последнем завершённом прогоне. Включает шесть настоящих upstream Extraction 1.2.0 fixtures, проверку legacy Linking 1.0.0 примера, API POST/GET round-trip, валидацию API-ответа опубликованной result schema, отдельные contract tests, псевдонимизацию LLM payload, независимые планы и Decimal арифметику. Предупреждений pytest нет. LLM mock не выдаётся за реальный модельный прогон.
- API тестами через ASGI: `/health`, `/docs`, `/openapi.json` работают; POST → GET сохраняет и возвращает ответ в формате result contract 1.0.0.
- Валидный пример результата специально показывает `manual_review` и `expected_value=null`: указанный целевой показатель относится к Q1, а акт-источник — к апрелю. Вычисленная сумма не публикуется как ожидаемая для несовпадающих периодов.
- Арифметическая воспроизводимость: числовые тесты отдельно фиксируют сумму пяти реальных строк акта `286500 + 93600 + 99600 + 158700 + 541900 = 1180300`.
- Сквозной LLM-прогон не выполнялся: в среде не настроены `LLM_API_KEY`, `OPENAI_API_KEY` или `POLZA_API_KEY`. Тест проверяет только блокировку закрытых данных и разрешение локального режима при явной настройке, не имитирует модель.

Тесты проверяют опубликованный JSON Schema напрямую и не зависят от Pydantic-модели реализации при contract validation. AI-планирование в реальном внешнем endpoint остаётся отдельной непроверенной интеграцией до появления разрешённой конфигурации. Docker smoke после изменения result contract не запускался.
