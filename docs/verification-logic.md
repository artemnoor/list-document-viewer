# Логика проверки

## Порядок допуска к сравнению

Для присвоения `matched` или `mismatch` движок разрешает actual и expected value, проверяет semantic key и тип, Extraction period, currency/unit, VAT basis, comparison basis, полноту расчёта и целостность calculation trace. Также проверяются source/document/extraction/row IDs, точный JSON Pointer, provenance, входные версии и fingerprints. Несовпадение или отсутствие обязательного fingerprint блокирует окончательный статус.

Техническая валидность источника, машинная проверка связи и human review хранятся отдельно в `trust`. `system_validated` может дать автоматическое подтверждение после локальной проверки ссылки на Extraction. Для Linking `status=confirmed` недостаточно: Verification требует совпадающие документы, input fingerprints и версии, разрешаемые path/evidence, точное исходное значение, отсутствие конфликтов и unresolved diagnostics. `verification_status=human_confirmed` сохраняется отдельно и не обязателен для полного автоматического результата.

Отсутствующий `link_id` допустим для источника, который не использовал Linking; любой заявленный `link_id` должен разрешиться и пройти проверки. Неиспользованные и `excluded_sources` не участвуют в доказательстве результата.

## Числовые правила

- Суммы приводятся к `Decimal` из исходной normalized amount; IEEE float не используется в вычислении разницы.
- `absolute = actual - expected`; относительная разница равна `(actual - expected) / abs(expected)`. При `expected = 0` она `null`.
- Валюты сравниваются только по точному коду. Автоматического FX пересчёта нет.
- Для `quantity` нужны одинаковые непустые единицы. Неизвестные конверсии не предполагаются.
- VAT `gross` и `net` несовместимы. `unknown` требует review.
- `actual` и `plan` — разные comparison basis; они не сравниваются как одно значение.
- Допуск отсутствует по умолчанию. Явная абсолютная tolerance применяется лишь при совпадении `absolute_unit` с валютой или измерительной единицей. Relative tolerance применяется лишь при ненулевом expected.
- `rounding_scale` и `rounding_mode` принимаются только если явно заданы. Сервис сохраняет raw difference даже когда округление её допускает.
- Разница, принятая по `absolute_tolerance` или `relative_tolerance`, остаётся в `difference`, но не создаёт доказанную категорию `amount_difference`/`quantity_or_indicator_difference`.

## Содержательные значения

- `period` сравнивается по `start`/`end`; подтверждённое различие периодов классифицируется `wrong_period`.
- `string` сравнивается после Unicode NFC и схлопывания пробелов, без перевода и нечеткого совпадения.
- `date` сравнивается как нормализованная строка. Boolean сравнивается по типу и значению.
- Несовпадающий semantic key или несовместимый type/economic basis ведёт к `not_applicable`, а не к числовому mismatch.

## Статусы показателя

| Статус | Условие |
| --- | --- |
| `matched` | Значения эквивалентны по явным правилам; calculation trace и все используемые source references проверены |
| `mismatch` | Значения или период доказанно отличаются на полной и проверенной базе |
| `insufficient_data` | Не хватает значения, расчёт неполный, источник/provenance отсутствует или ссылка не разрешается |
| `needs_review` | Неоднозначная/неподтверждённая связь, конфликт, неизвестный basis или необходимость экспертного решения |
| `not_applicable` | Экономический смысл, тип, валюта, единицы или basis несовместимы |

Наличие численной разницы при неполной базе оставляет `difference` для диагностики, но не доказывает `amount_difference` и не создаёт окончательный `mismatch`. На уровне запуска `completeness` показывает полное количество, проверенный охват и неразрешённые/`not_applicable` показатели. Любой `not_applicable` запрещает общий `matched`.

Необязательный narrative provider Polza AI может предложить только гипотезу. Внешний запрос содержит псевдонимные tokens, статусы, категории и коды диагностики; financial values, IDs документов, source text и секреты не передаются. Ответ не влияет на значение, формулу, разницу или статус. Вызов выполняется вне SQLite транзакции, ограничен timeout и пропускается, когда не хватает времени; ошибка провайдера не отменяет детерминированный результат.

## Общий статус запуска

Сводный статус требует полного применимого охвата. `insufficient_data` и `needs_review` блокируют итог, затем учитывается `not_applicable`; `mismatch` возможен только при отсутствии непроверенных/неприменимых показателей. Общий `matched` возможен лишь когда каждый показатель проверен и сопоставлен. Отсутствующий Reconciliation target создаёт `insufficient_data` и не скрывается из сводки.
