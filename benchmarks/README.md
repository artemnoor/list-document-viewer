# Бенчмарки и доказательства

Каталоги: [публичные сценарии расчёта](cases.json), [модельное сравнение](models/compare.mjs), [результаты](results), [корпус Document Parser](document-parser). Последний каталог ранее назывался `бенчмаркс`; пути в скриптах Parser обновлены.

Три самостоятельных уровня проверки: точность локального расчёта на опубликованных входах, повторная сверка контрольного комплекта и запуск нового Docker-стека. Модельный эксперимент публикуется отдельно, чтобы результат детерминированного расчёта не выдавался за точность LLM.

## 1. Публичный синтетический корпус — 15/15

```sh
python benchmarks/run.py
```

Нужен только Python 3.11+. Ключ, сеть и зависимости OCR не требуются. [Входы и независимые ожидаемые ответы](cases.json) · [проверяющий скрипт](run.py) · [зафиксированный результат](results/financial-audit.json).

| Сценарий | Ожидаемое поведение |
|---|---|
| 01. Независимые акты | 70 000 + 50 000 = 120 000, совпадение |
| 02. Доказанное расхождение | 132 500 против 120 000, разница 12 500 |
| 03. Копия с другим OCR-текстом | Операция учитывается один раз |
| 04. Чужой период | Документ исключается, верная сумма сохраняется |
| 05. Другой договор | Документ исключается с причиной |
| 06. Неизвестный период | Недостаточно данных, ожидание не выдумывается |
| 07. Отрицательная корректировка | 130 000 − 10 000 = 120 000 |
| 08. Разные валюты | Проверка требует данных о преобразовании |
| 09. Округление HALF_UP | −10,005 → −10,01 |
| 10. Конфликт сумм одной операции | Требуется проверка |
| 11. Неодинаковые реквизиты поставщика | Независимость операций не предполагается |
| 12. Разные ИНН поставщиков | Одинаковые номера не означают дубль |
| 13. Неподтверждённая статья | Общий итог остаётся непроверенным |
| 14. Неподтверждённый ноль | Не заменяется достоверным нулевым расходом |
| 15. Неполная зарплатная ведомость | Один день не подтверждает весь месяц |

Оценщик сравнивает статус, ожидание, разницу и категории, затем разрешает каждую ссылку до точного исходного значения. В протоколе сохранены SHA256 корпуса и реализации. Ответы заданы в корпусе до исполнения; код расчёта не читает gold. Генератор [generate_cases.py](generate_cases.py) публикуется для проверки происхождения синтетики.

Это тест локального расчёта **после извлечения**, а не оценка OCR или качества моделей на произвольных документах.

## 2. Контрольный комплект КФЗ

Зафиксирован [протокол](results/case19.json): пять сумм/статусов/разниц и четыре дополнительные проверки прошли; 93 ссылки проверены; PDF, Markdown и JSON доступны. Три статьи совпали, одно завышение 12 500 ₽ отражено в статье и итого, десять показателей оставлены неподтверждёнными.

При наличии исходного набора кейса:

```sh
python -m pip install httpx openpyxl
cd phystech-trace
python tests/e2e/run_case19.py --dataset <каталог-кейса> --classification public --report-row "3 этап 2026" --period-start 2026-01-01 --period-end 2026-05-31 --output case19.json
python tests/e2e/evaluate_case19.py --result case19.json --gold <файл-эталона.xlsx>
```

Эталон не загружается как первичка и не передаётся модели. Опубликованный протокол получен повторным расчётом сохранённых извлечений через реальный API; новый полный OCR/LLM-прогон — отдельная команда выше. Исходный пользовательский корпус и runtime-uploads в публикацию не добавляются.

## 3. Docker с новыми томами

```sh
python scripts/verify_docker.py --build
```

Скрипт создаёт случайное имя Compose-проекта, отключает публикацию портов, использует пустой env-файл без модельного ключа и новые тома. Собирает образы, ждёт healthchecks, проверяет Parser, Extraction, Linking, Reconciliation, Verification, Gateway и frontend. После завершения удаляет только собственный временный проект.

[Протокол Docker smoke](results/docker-smoke.json): сборка и 7/7 HTTP-проверок прошли, очистка завершилась успешно. Проверка выполнена на том же Docker Engine, но без томов и файлов `.env` рабочего приложения.

## 4. Сопоставимый модельный эксперимент

```sh
# POLZA_API_KEY должен быть задан в окружении.
node benchmarks/models/compare.mjs --repeats=2 --output=benchmarks/results/model-comparison.json
```

Шесть коротких русскоязычных задач × два повтора × две модели. Одинаковые prompt, temperature, бюджет ответа и gold; все ответы, ошибки и времена сохраняются. [Программа](models/compare.mjs) · [полный результат](results/model-comparison.json) · [разбор моделей](../docs/models.md). Исходный предварительный прогон также [сохранён](results/model-comparison.initial.json), включая обрезанные ответы; итоговый протокол использует явные ID источников и общий бюджет 2048 токена.

## Дополнительные проверки

```sh
python -m pip install -r phystech-trace/tests/requirements.txt
cd phystech-trace
python -m pytest tests -q
cd services/document-linking
npm ci
npm test
npm run build
```

Gateway/расчёт — 80 прошедших тестов, включая 19 новых регрессий. Linking после чистой установки — 95 прошедших, 5 инфраструктурных/live-пропусков; сборка прошла. Команды CI находятся в [GitHub Actions](../.github/workflows/integration.yml). Число unit-тестов, семантическая точность LLM и точность OCR — разные измерения.
