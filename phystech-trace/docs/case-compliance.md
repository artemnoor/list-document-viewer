# Соответствие кейсу и проверка полного комплекта

Источник требований: https://docs.google.com/document/d/19n0jbisDtWv9DuSL6Jt0FfHIAqjtBYLF/edit

## Реализованное поведение

Система принимает КФЗ и первичные PDF, XLSX, DOCX, PNG, извлекает значения с provenance, фильтрует договор, период и дубли, рассчитывает ожидаемые значения и выдаёт статус каждого показателя. Для явно определяемых статей затрат доступна локальная сверка `local-cost-audit/1.1`; неоднозначность и неполное покрытие периода сохраняются как недостаточность данных. Для других структур доступен расширенный семантический режим.

| Требование | Реализация |
| --- | --- |
| Статус каждой строки | Совпадает, расхождение, недостаточно данных; подпоказатели без подтверждений сохраняются отдельно |
| Факт, ожидание, разница | Decimal, сумма независимых документов, округление HALF_UP до копеек |
| Агрегирование | Месячные ведомости, документы одной статьи; итоги и их компоненты не складываются повторно |
| Период и договор | Явно заданная строка/этап и период в интерфейсе/API, проверка реквизитов; чужой договор/период исключаются с причиной |
| Дубли | Идентичный файл учитывается один раз; имя копии и SHA-256 сохраняются в аудите. Для разных файлов проверяются номер, период, договор, содержание и сумма |
| Источник расхождения | Имя и ссылка на документ, точный JSON Pointer, исходное значение, страница/координаты либо лист/ячейка, формула |
| Итоговое заключение | Сводка корректных, ошибочных и непроверенных показателей, причины исключений, скачиваемый Markdown и JSON |
| Надёжность | Ошибки распознавания/модели не превращаются в нулевое ожидание; неустановленная валюта и конфликтные значения остаются непроверенными |
| Развёртывание | Docker Compose, инструкции запуска/остановки, настройки, схема потока данных и типовые сценарии |

## Воспроизведение

```powershell
cd phystech-trace
docker compose up -d --build
python tests/e2e/run_case19.py --dataset <каталог> --classification public --report-row "3 этап 2026" --period-start 2026-01-01 --period-end 2026-05-31 --output case19.json
python tests/e2e/evaluate_case19.py --result case19.json --gold <файл-правильных-ответов.xlsx>
```

Для оценки нужен `openpyxl`; для запуска — `httpx`. Файлы README и правильных ответов автоматически исключаются из загрузки. Локальный результат доступен в проекте, `GET /api/projects/{id}/financial-audit` и скачиваемом `GET /api/projects/{id}/report.md`.

## Практические границы

Успешный кейс подтверждает поведение на данном комплекте, не универсальную точность на любых документах. Локальные правила поддерживают явно определяемые статьи оплаты труда, страховых взносов, производственных и административных накладных затрат. Неизвестная статья, неоднозначная сумма, масштаб в тысячах/миллионах или неполные реквизиты требуют проверки. Расширенный модельный режим сохраняет ограничения качества/контекста провайдера; его полнота на большом комплекте не заявляется.

Развёртывание проверено в текущем Docker-окружении, не на отдельной чистой машине. Внешняя Polza AI разрешена пользователем для прототипа, включая confidential. Для формального соблюдения ограничения кейса confidential необходимо перевести на локальные модели перед промышленным использованием.

## Итоговые проверки

После исправлений аудита Gateway и локальный расчёт: 80 тестов прошли, включая 19 новых проверок дублей, периода и полноты итога. Document Linking после чистой установки по lockfile: 95 прошли, 5 пропущены (инфраструктурные/live-проверки); сборка успешна. Gateway пересобран и перезапущен, сохранённый кейс повторно пересчитан через API на `local-cost-audit/1.1`: пять контрольных сумм/статусов/разниц и четыре дополнительные проверки эталона прошли; 3 совпадения, 2 расхождения, 10 непроверенных показателей. Markdown, PDF и JSON возвращают HTTP 200. Результат: `output/case19-postfix-evaluation.json`.

Предыдущие проверки остальных компонентов: Structured Extraction — 77 прошли; Reconciliation — 104 прошли; Verification — 72 прошли; Parser — 178 прошли; сборка Vue/TypeScript успешна. Эти компоненты данным исправлением не менялись. Ранее интерфейс проверен Playwright на широком экране и ширине 390 px. Новый полный прогон OCR и внешних моделей не выполнялся: повторно использованы сохранённые извлечения и оригиналы.
