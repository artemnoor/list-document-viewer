# Единая точка входа

http://localhost:8080/ — лендинг; кнопки «Зарегистрироваться» и «Войти» открывают `/register` и `/logIn`. После регистрации или входа открывается http://localhost:8080/app/. Кабинет использует существующий Gateway через `/api/`. Проекты, документы и результаты остаются в прежних хранилищах.

## Структура

```text
phystech-trace/
  landing/                     # Публичные HTML-страницы и локальные ресурсы
    local-assets/              # Перевод, оформление, изображения продукта
    _mirror/                   # Библиотеки, шрифты, медиа снимка
    upstream.json              # Репозиторий и commit импорта
  frontend/                    # Vue-кабинет и общая web-сборка
    src/                       # Проекты, документы, связи, сверка
    scripts/integrated-site.ts # Лендинг в dev/preview и сборке
    scripts/check-site.mjs     # HTTP-проверка и доступ к Gateway
    nginx.conf                 # Общая маршрутизация Docker
    dist/                      # Результат сборки, исключён из Git
      index.html               # Лендинг
      app/                     # Кабинет, JavaScript, CSS и бренд
  gateway/                     # Общий API и оркестрация
  services/                    # Сервисы обработки документов
  contracts/                   # Межсервисные контракты
  tests/                       # Контрактные и сквозные проверки
```

Parser продолжает использовать корневой `backend/`. Корневой `frontend/` — прежний автономный просмотрщик Parser. Основной интерфейс системы — `phystech-trace/frontend/`.

## Маршруты

| URL | Назначение |
| --- | --- |
| `/` | Лендинг |
| `/compare`, `/blog`, `/case-studies` | Публичные страницы |
| `/app/` | Кабинет с сохранёнными проектами |
| `/app/?project=<id>&tab=verification` | Сверка выбранного проекта |
| `/?project=<id>&tab=verification` | Перенаправление с сохранением проекта и вкладки |
| `/register`, `/logIn` | Регистрация и вход |
| `/recover`, `/book-a-demo` | Переход к регистрации |
| `/api/` | Proxy в Gateway |
| `/health` | Health Gateway |

Регистрация требует только непустые почту и пароль; телефон, подтверждение почты, капча и требования к сложности пароля отсутствуют. После регистрации сразу создаётся сессия на 30 дней в HttpOnly cookie. Пароли хешируются scrypt с индивидуальной солью; в PostgreSQL сохраняется только хеш токена сессии. Выход отзывает сессию. Прямой переход в кабинет без сессии открывает вход, сохраняя адрес проекта и вкладки в `next`.

Это аккаунты общего рабочего пространства: существующие проекты доступны всем вошедшим пользователям. Разделение проектов по владельцам и изменение доступа к существующему сервисному API не добавлялись. Имя профиля хранится в браузере отдельно для каждого аккаунта.

API аккаунтов: `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me`, `POST /api/auth/logout`. Таблицы `trace_users` и `trace_sessions` создаются при старте Gateway; дополнительный сервис не нужен.

## Запуск

Из `phystech-trace/`:

```powershell
docker compose up --build -d
```

Обновление только web-интерфейса при работающих сервисах:

```powershell
docker compose build frontend
docker compose up -d --no-deps frontend
```

Разработка из `phystech-trace/frontend/`:

```powershell
npm ci
npm run dev
```

Лендинг: `http://localhost:5173/`, кабинет: `/app/` на том же порту. Gateway должен работать на `127.0.0.1:8084`. Для занятого порта: `npm run dev -- --port=5184 --strictPort`.

```powershell
npm run build
npm run preview
npm run check:site
npm run check:site -- http://127.0.0.1:5184
```

`check:site` проверяет публичные страницы, MIME ресурсов, переходы старых URL, отсутствие подмены отсутствующих скриптов HTML, Gateway и сохранённые проекты. Проверка только читает данные и не запускает AI-обработку. `preview` показывает собранные страницы; HTTP-проверку с API запускайте против dev-сервера или Docker nginx.
