# Архитектура Phystech Trace

## Границы модулей

| Модуль | Код и ответственность | Хранилище / очередь | HTTP |
| --- | --- | --- | --- |
| Document Parser | Существующий `backend/`: Docling, OCR, нативный разбор PDF/Office, source layout и просмотр страниц | Отдельный volume `parser-uploads`; модели Docling в `parser-models` | `:8081`, Swagger `/docs` |
| Structured Extraction | Импортированный исходный адаптер Document Parser, классификация, rules/Polza extraction, исходные и нормализованные значения | Таблица `trace_extractions` в PostgreSQL | `:8082`, Swagger `/docs` |
| Document Linking | Импортированный LLM resolver, валидация evidence и ручные решения | PostgreSQL и Redis/BullMQ | `:8083`, Swagger `/docs` |
| Gateway | Проекты, загрузка, межсервисная оркестрация, прогресс и повторы этапов | Таблицы `trace_projects`, `trace_documents` в PostgreSQL | `:8084`, Swagger `/docs` |
| Reconciliation Engine | Планирование расчёта, фильтрация источников, агрегирование и округление; сохраняет формулу и причины исключений | Постоянный volume результатов | `:8085`, Swagger `/docs` |
| Verification Engine | Проверка источников, сравнение значений, категории расхождений и итоговое заключение | Постоянный volume результатов | `:8086`, Swagger `/docs` |
| Landing | Локальная копия публичных страниц в `landing/`, шрифты, медиа, русский текст | Статические файлы | `:8080`, `/` |
| Frontend | Vue 3 + TypeScript + Vite; показывает результаты API и отправляет решения специалиста | Нет локальной бизнес-логики или хранения документов | `:8080`, `/app/` |

Сервисы находятся в одной Compose-сети. Каждый исходный модуль запускается отдельным контейнером и сохраняет свою ответственность. Parser остаётся в существующем `backend/`, чтобы не менять его публичные пути и локальный интерфейс; Dockerfile и OpenAPI отдельного Parser API находятся в `services/document-parser/`.

Gateway управляет стадиями Parser → Extraction → Linking → Reconciliation → Verification. Reconciliation строит план расчёта и исполняет арифметику через Decimal; Verification сравнивает фактическое и ожидаемое значения, проверяет evidence и формирует заключение. Состояние каждого этапа и промежуточные результаты записываются до перехода дальше. После перезапуска Gateway восстанавливает незавершённые проекты. Повтор этапа пропускает уже сохранённые результаты ранних стадий. Linking сохраняет BullMQ checkpoints и возобновляет ошибочное задание.

PostgreSQL — общее постоянное хранилище результатов. Redis используется очередью Linking; Gateway не копирует алгоритм очереди. Parser сохраняет оригиналы и OCR-кеш на отдельном volume. Система не требует Cloudflare Workers, D1, ChatGPT или Cloudflare инфраструктуры.

Лендинг и кабинет собираются вместе и обслуживаются одним nginx. `/api/` проксируется в Gateway. Старые адреса проектов сохраняют параметры и перенаправляются в `/app/`. Подробности: [web-integration.md](web-integration.md).

## Внешняя модель и данные

В текущем прототипе оба класса данных могут обрабатываться внешней Polza AI при разрешении пользователя. Для confidential выбрана Gemma, для остальных классов — DeepSeek. Gateway вызывает дополнительную AI-проверку распознавания, затем модель может участвовать в извлечении, связывании, планировании и пояснениях. Ошибка дополнительной проверки сохраняется предупреждением и не удаляет OCR. Для соблюдения ограничения кейса confidential необходимо перевести на локальные модели; текущая внешняя обработка является согласованным допущением прототипа.

## Сеть и доступ

Пользовательские порты привязаны к `127.0.0.1`. PostgreSQL, Redis и Linking worker наружу не публикуются. Linking API защищён bearer token. Для загрузки ресурсов Swagger UI браузеру нужен доступ к `unpkg.com`.


## Локальная сверка статей

После Extraction Gateway может использовать `gateway/financial_audit.py`. Модуль читает только сохранённые значения и provenance, правила классификации операций и область проекта; выполняет фильтрацию/агрегирование/сравнение без модельных запросов. Результат хранится отдельно в `trace_projects.financial_audit`, не выдаётся за контракт семантического сервиса. UI явно показывает локальный расчёт. Для других структур выбирается `calculation_mode=semantic`.
